## Graph and common contract

`preflight → research → reports → ingestion → publication-and-retrieval → restoration → fresh-consumer-evaluation`, with an additional required `research → ingestion` edge. Each composition runs the full graph separately against isolated fixture state. Every stage is a separate thread/run. Each stage file binds upstream seals by digest, question ids, cutoff, model/route and price pins, skill/MCP/snapshot pins and remaining budget. Stage execution is sequential with manual continuation; async children run within a stage.

For every row below, the coordinator uses `$root`: GPT-6 Sol or Claude Opus 5.5. Every child uses `$subagent`: GPT-6 Luna or Claude Sonnet 5. Coordinator skill is `knowledge-research`, except the isolated fresh consumer. The child column assigns additional canonical Unit 6 skills explicitly. All coordinators are shell-less, non-sandboxed compiled DeepAgents. “Compiled async” means a separately served compiled DeepAgent registered with the parent's native `AsyncSubAgent` descriptor; “compiled sync” means a `CompiledSubAgent` runnable. Dict checks are sync and shell-less on their parent's backend with explicit tools/interrupts.

Every durable output below is a KS custody handle (`id`, `sha256`, media type, producer run/thread/agent/checkpoint), listed in the stage seal alongside service receipts and child identities. Local sandbox paths are scratch only. Every validator re-reads KS, verifies digests/authority and rejects unresolved required operations, missing receipts or non-terminal children. A structural seal is not verification admission or fixture acceptance.

Catalog groups below are selection sources, **not grants**. Resolve exact operations and available transport bindings against `packages/application/src/operations/catalog.ts` at the pinned KS commit. Only admitted/composed capabilities are runnable. `operations` allows the required status/receipt reads; mutation/control permissions must be separately granted. Publication/reviewer operations excluded from MCP use service-authorized HTTP/CLI under distinct principals, never a generic-submit bypass. No Jev call is required in this graph; its canonical skill and existing capability remain preserved.

## Budget and run order

Combined ceiling **$25 = $7 OpenAI + $15 Anthropic + $3 reserve** for recovery/reruns. The seven-stage allocation refines the proof plan's coarser research/reports/ingestion split; it does not add to it. Parent and child costs share each stage ceiling; include tool/sandbox spending in the overall cap. Reserve use requires recorded allocation. Run OpenAI first; launch Anthropic only after the OpenAI graph validates within ceiling and its own DR1 route passes. Insufficient budget is a stop with preserved evidence, not permission to omit required stages or children.

## Operator instructions for the future runner

1. Complete the readiness records, freeze the corpus/questions/cutoff and choose the disposable targets. Pin source/lockfile, stage configs, skills, catalogs, routes/prices and sandbox snapshots. Start the LangGraph Postgres checkpointer/store on its separate Docker database and the proven async Agent Protocol service. Never reuse shared Supabase for either fixture state or agent persistence.
2. Materialize/validate each parent and child configuration. Require KS connectivity (no optional skip), exact tool allowlists and skill digests. Resolve the proposed schema extension before feeding configs to the current v1 parser.
3. Run proposed `graph status`, then `graph next --composition <openai|anthropic>` (final CLI syntax is DR4's responsibility). Inspect the generated input manifest, stage ceiling and validator result; explicitly confirm launch. The runner must not dispatch on status alone.
4. Resume a paused stage or approve/reject its interrupt. Fork only with recorded tool constraints, child ownership and budget carried forward. Track async task identities to terminal status; never seal a stage while paid children are still running. Retrieve child structured outputs and custody handles.
5. Re-read KS, validate and seal that stage before continuing. A failed predecessor blocks dependents. For ingestion, check research and report pins even when reports already referenced research. Preserve failed attempts and allocate retries explicitly.
6. After restoration and fresh-consumer evaluation, settle spend, reconcile unresolved operations, stop fixture-owned jobs/sandboxes and record both composition outcomes. Preserve custody, receipts, checkpoints and immutable evidence before cleaning disposable infrastructure.

Outputs are **provisional engineering results**, distinct from full fixture acceptance: human-reviewed gold, frozen-corpus acceptance, lanes A–E and release gates must be evaluated under the meta specifications. Mission Control work begins after this fixture work and its limitations are recorded; do not call a successful agent message Mission Control Stage Acceptance.
