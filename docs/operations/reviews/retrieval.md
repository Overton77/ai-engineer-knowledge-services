# Module review: retrieval

Module and reviewed revision: `@aiengineer/knowledge-retrieval` at `ff7fe97` plus the uncommitted 2026-09-19 Phase 2 split (`packages/retrieval/src/**`, `packages/retrieval/examples/**`, `packages/retrieval/{package.json,tsconfig.examples.json}`). No behavior change from the pre-split package; see "What changed" below.

Purpose, owner, callers, and supported interfaces: Knowledge Services owns the in-memory advanced retrieval pipeline used for evaluation and exploratory-index retrieval: policy-scoped plan assembly, lexical/semantic/graph channel scoring, reciprocal-rank fusion, diversity capping, context-radius attachment, coverage-based abstention, and immutable evidence-packet assembly. **No app imports this package.** The canonical HTTP retrieval path (`apps/api/src/retrieval-executor.ts`) runs through `@aiengineer/knowledge-persistence`, not through `retrieval`. Callers: `packages/application/src/preparation/knowledge.ts` (`AgenticKnowledgeService`, imports `retrieve`, `ImmutableEvidencePacket`, `RetrievalPolicy`, `RetrievalRecord`), and `packages/testkit/src/{retrieval-fixtures.ts,broad-evaluation-corpus.ts}` (imports `retrieve`, `GraphEdge`, `RetrievalFilter`, `RetrievalPolicy`, `RetrievalRecord`, `RetrievalStages`). Public interface: `retrieve`, `buildRetrievalPlan`, and the 17 retrieval contract types (`RetrievalIntent`, `FilterValue`, `RetrievalFilter`, `RetrievalSubquery`, `AdvancedRetrievalPlan`, `RetrievalPolicy`, `RetrievalRecord`, `RetrievalFlags`, `GraphEdge`, `RetrievalChannel`, `StageContribution`, `RetrievedCandidate`, `EvidenceMember`, `ImmutableEvidencePacket`, `Reranker`, `RetrievalStages`, `RetrieveOptions`) — unchanged from before the split; proven by declaration diff below.

Affected agent skills: **none.** No skill in `skills/manifest.json` or `apps/verification-executor/skills/manifest.json` names a symbol from this package (`store search` and `space rebuild` stay `unsupported`; `promotion_selection_select` stays absent). `skills/check.mjs` numbers are unaffected by this unit.

## What changed

Per `PHASE-2-RECOMMENDATION.md` §3.1 (P2-1): the single 863-line `src/index.ts` is split into `types.ts`, the whole `retrieve()` orchestrator in `retrieve.ts`, and six stage-primitive folders (`spaces/`, `plan/`, `lexical/`, `semantic/`, `graph/`, `rerank/`), each with its own `index.ts` barrel and co-located tests. `retrieve.ts` keeps its exact control flow: one `channelRanks` Map it owns, `rankChannel` closing over it, and every extracted primitive (`expandVerifiedGraph`, `score`, `exactScore`, `ftsScore`, `trigramScore`, `cosine`, `sum`, `compareCandidate`, `rrfContribution`) called from there in the original order. `ALL_SPACES` is now derived from `VectorSpaceSchema.options` (P2-9) instead of hand-copied. The unused `@aiengineer/knowledge-vector-backends` dependency was left in place (P2-10). `examples/` was added with three runnable, tested scenarios. No public export changed; no assertion in the six moved pipeline tests changed.

One deliberate deviation from a literal reading of "types.ts // lines 1–202 verbatim": the original line 1 import (`deepFreeze, sha256Digest` from `@aiengineer/knowledge-domain`) is not part of `types.ts`'s own import list, since neither name is used by a type declaration; `types.ts` imports only `SourceLocator`/`VectorSpace` from `@aiengineer/knowledge-contracts`. Every type declaration itself is verbatim.

Normal path: `retrieve(query, options)` → `buildRetrievalPlan` (space/filter admission, subquery decomposition, intent inference) → tenant/visibility/space/hard-filter admission → lexical (exact/trigram/fts) and semantic (cosine) channel scoring into `channelRanks` → optional verified-graph expansion → optional reranker fusion → RRF-fused, penalty-adjusted, tie-broken candidate ranking → source-diversity cap → context-radius attachment → coverage/evidence/abstention computation → frozen `ImmutableEvidencePacket` with a stable digest. Failure path: `QUERY_REQUIRED`, `SPACE_NOT_ADMITTED:<list>`, `FILTER_NOT_ALLOWED:<field>`, `RETRIEVAL_LIMIT_EXCEEDED`, `INVALID_RRF_POLICY`, `INVALID_COVERAGE_POLICY`, `INVALID_EVIDENCE_SCORE_POLICY`, `INVALID_EVIDENCE_TERMS_POLICY` all thrown synchronously from `buildRetrievalPlan` before any stage runs; a reranker failure degrades in place (`degradedMode: true`, `reranker_failed_fused_results_used` omission) rather than throwing; `cosine` throws `QUERY_VECTOR_DIMENSION_MISMATCH`/`NON_FINITE_VECTOR` for malformed vectors.

Remaining debt (carried forward, not fixed by this unit):
- `packages/retrieval/package.json` still declares `@aiengineer/knowledge-vector-backends` as a dependency that `src/` never imports (P2-10; recommended removal is Phase 3, with the lockfile change).
- Memo §7 item 1: the graph stage's `seen.size >= policy.maxGraphNodes` check is positioned inside the edge loop, so it bounds newly seen nodes rather than total expansion work; a dense edge set still walks every edge at each depth. Unchanged, now also documented at the unit-test level (`graph/expand.test.ts`).
- Memo §7 item 2: `plan.graph.maxDepth` is hard-capped to `Math.min(1, policy.maxGraphDepth)` regardless of the policy's stated `maxGraphDepth` (test fixtures use 2), silently making depth-2 policies unreachable. Unchanged; now called out in a comment in `plan/build-plan.ts` and covered by a unit test that documents the freeze.
- Memo §7 item 3: `evidenceScore`/`evidenceTerms` are computed over `selected`, which is already capped by `finalK` and the diversity rule, so raising `maxPerSource` can change an abstention decision without new evidence entering the corpus. Unchanged; no new test added, per the instruction not to fix or newly assert on findings 1–3 beyond recording them.
