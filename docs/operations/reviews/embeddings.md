## Must-haves

Derived from `SPECIFICATION.md` §5.3 ("Validate ordered finite embedding outputs, model/dimension/configuration, expected input membership") and the credential-handling discipline already established for `conversion` (`docs/operations/reviews/conversion.md`, CONV-SECRETS). Assessment reflects what `src/vectors.test.ts`, `src/cache.test.ts`, `src/gateway.test.ts`, `src/fake.test.ts`, and `examples/*.test.ts` actually assert.

| ID | Must-have | Given / when / then | Assessment |
|---|---|---|---|
| EMBED-ORDER | Batch output is ordered and finite; reordered, partial, or non-finite provider responses are rejected | Given a response with a swapped `index`, a short `data` array, or a non-finite value, when embedded, then `EMBEDDING_ORDER_MISMATCH`, `EMBEDDING_COUNT_MISMATCH`, or `EMBEDDING_NON_FINITE` is thrown | present: `gateway.test.ts` "rejects reordered, partial and malformed output atomically"; example 03 (`03-reject-bad-output.ts`) exercises all four malformed shapes including wrong dimension |
| EMBED-DIMENSION | Every embedding matches `expectedDimensions`; a wrong-length vector is rejected | Given a vector of the wrong length, when validated, then `EMBEDDING_DIMENSION_MISMATCH` | present: `vectors.test.ts` "rejects wrong dimensions and non-finite values"; example 03 |
| EMBED-MODEL-PIN | `modelSlug` and `expectedDimensions` default to and are carried through as `DEFAULT_EMBEDDING_MODEL` / `DEFAULT_EMBEDDING_DIMENSIONS` when the caller omits them, and are recorded in the receipt's `modelDigest` | Given a request without `modelSlug`, when embedded, then the receipt's `modelSlug` is the default and `modelDigest` reflects it | present by construction in `gateway.ts`/`fake.ts`; exercised indirectly by every `embedMany` test asserting receipt shape |
| EMBED-IDEMPOTENT | One idempotency key is reused across every retry attempt of the same logical request | Given a `503` then success, when embedded, then both HTTP calls carry the same `idempotency-key` header | present: `gateway.test.ts` "retries with one idempotency key, validates provider order, and caches per version"; example 02 (`02-cache-and-retry.ts`) |
| EMBED-CACHE | A repeat request for the same `vectorSpaceVersionId` and input digest is served from the cache without another network call; a different `vectorSpaceVersionId` is not | Given the same request twice, when embedded, then the second call makes no HTTP request and every item is `cached: true`; given a different `vectorSpaceVersionId`, then a new HTTP call is made | present: `gateway.test.ts` (same test); `vectors.test.ts` "namespaces the cache key by vectorSpaceVersionId"; example 02 |
| EMBED-RETRY-BACKOFF | A numeric `retry-after` header is honoured and capped at 10s; otherwise backoff is exponential and capped at 2s; a non-retryable status throws without retrying | Given `retry-after: 3` then `retry-after: 60`, when computing delay, then `3000` then `10000`; given no/unparseable header, then capped exponential backoff; given a `400` response, when embedded, then it throws after exactly one call | present: `gateway.test.ts` "retryDelay" describe block; "throws without retrying on a non-retryable status" |
| EMBED-CREDENTIALS | Credentials never appear in a receipt, a discovery result, or an error message | Given a `discoverModel` call with a real-looking API key, when the result is serialized, then it does not contain the key | present: `gateway.test.ts` "discovers the configured model without exposing credentials" |
| EMBED-USAGE-UNKNOWN | An unreported provider usage is recorded as `"gateway:unreported"`, never silently reported as zero-cost/zero-route | Given a gateway response with no `providerMetadata`/`provider_metadata` and pending misses, when embedded, then `observedProviderRoute` is `"gateway:unreported"` rather than a fabricated route | present by construction in `gateway.ts` (`missingIndexes.length ? "gateway:unreported" : "cache"`); covered indirectly wherever a gateway test omits `providerMetadata` |
| EMBED-CREDENTIAL-MISSING | Constructing an adapter or the environment factory without a credential fails closed | Given neither `AI_GATEWAY_API_KEY` nor `VERCEL_OIDC_TOKEN`, when creating the adapter from environment, then `AI_GATEWAY_CREDENTIAL_MISSING`; given `VERCEL_OIDC_TOKEN` alone, then it succeeds | present: `gateway.test.ts` "createGatewayEmbeddingAdapterFromEnvironment" describe block |
| EMBED-DUPLICATE | Duplicate `projectionId`s or a caller-supplied digest mismatch in one request are rejected before any network call | Given two inputs with the same `projectionId`, or a `textDigest` that disagrees with the text, when embedded, then `DUPLICATE_EMBEDDING_PROJECTION` or `EMBEDDING_TEXT_DIGEST_MISMATCH` | present: `fake.test.ts` "rejects caller-supplied digest mismatches and duplicate projection identities" |
| EMBED-DETERMINISTIC | The fake adapter is deterministic: same inputs give the same ordering and the same output manifest digest on replay | Given the same batch run twice, when embedded, then `outputManifestDigest` is identical and item order matches input order | present: `fake.test.ts` "returns stable ordered deterministic embeddings and manifests"; example 01 |

Normal path: caller builds a request → `validateRequest` → cache lookup per `(vectorSpaceVersionId, inputDigest)` → gateway POST for cache misses only, retried under one idempotency key → `validateGatewayData` (order, count, dimension, finiteness) → items cached and returned in a deterministic `EmbedBatchReceipt`. Failure path: `IDEMPOTENCY_KEY_REQUIRED` / `VECTOR_SPACE_VERSION_REQUIRED` / `EMBEDDING_INPUTS_REQUIRED` / `EMPTY_EMBEDDING_INPUT` / `EMBEDDING_TEXT_DIGEST_MISMATCH` / `DUPLICATE_EMBEDDING_PROJECTION` from `validateRequest`; `EMBEDDING_COUNT_MISMATCH` / `EMBEDDING_ORDER_MISMATCH` / `EMBEDDING_DIMENSION_MISMATCH` / `EMBEDDING_NON_FINITE` from output validation; `AI_GATEWAY_DISCOVERY_<status>` / `AI_GATEWAY_EMBED_<status>` from the gateway; `AI_GATEWAY_CREDENTIAL_MISSING` from construction.
