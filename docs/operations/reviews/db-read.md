# Module review: db-read

Module and reviewed revision: `@aiengineer/knowledge-db-read` at `ff7fe97` plus the uncommitted 2026-09-19 Phase 2 addition (`packages/db-read/src/space-manifest.ts`, `packages/db-read/src/space-manifest.test.ts`, one added line in `packages/db-read/src/index.ts`). No existing file moved and no existing export changed; the new file is additive only (Phase 2 memo §6, decision P2-7).

Purpose, owner, callers, and supported interfaces: Knowledge Services owns the catalog-driven bounded read of the pinned database: `knowledge-read-intent.v1` in, `knowledge-read-snapshot.v1` out, one digested snapshot per transaction, plus guarded read-only SQL, `EXPLAIN`, the tenant knowledge head, and the artifact ledger. Callers: `packages/ingestion` (~21 files) uses `ReadExecutor` to read named catalog queries as part of deterministic ingestion; `apps/verification-executor/src/knowledge/**` (~8 files, `operations.ts:30-90` in particular) exposes `schema_manifest`, `db_head`, `db_read_intent`, `db_sql_readonly` as executor operations over this package; `scripts/prove-current-schema.mjs` runs it directly. Public interface: `ReadExecutor` (`workspace` getter, `catalog()`, `databaseHead()`, `head()`, `validateIntent()`, `runIntent()`, `sqlReadonly()`, `explain()`), `ArtifactLedger` (`put`/`putWith`/`get`/`reconcile`/`link`), `assertSingleReadStatement` (the SQL guard), `ReadIntentSchema`/`ReadOperationSchema`/`OperationResult`/`ReadSnapshot` types, `canonicalJson`/`digestOf` (RFC 8785 digesting), `uuidv7`, `validatePersistedSnapshot`, `bindKnowledgeClock`/`snapshotDigest`, and — new in this revision — `buildSpaceManifest`/`readSpaceManifest` and the `SpaceManifest*` types.

Affected agent skills: `schema-explore` and `knowledge-db` name `schema_manifest` / `db_head` / `db_read_intent` / `db_sql_readonly` as the operations they teach navigation over. **No skill names `space_manifest`** and none changes in this unit: the executor registry entry, CLI surface, and MCP surface for `space_manifest` are explicit follow-up work for the registry owner (see "Executor operation follow-up" in the unit result file), and `apps/verification-executor/src/knowledge/operations.ts` is a Track K reserved file before gate G3 that this unit does not touch. `node skills/check.mjs` is unchanged at `11/42/58/78/70`.

Normal path (existing): `runIntent` validates the intent statically (schema, catalog membership, params, role lattice, limits) with no I/O, then opens one read-only `repeatable read` transaction, reads the head before and after, executes each operation under its bounded role with a savepoint per operation, and returns a `knowledge-read-snapshot.v1` whose `snapshotDigest` covers every operation's identity and content digest. Failure path (existing): `INTENT_SCHEMA_INVALID`, `WORKSPACE_STALE`, `ROLE_DENIED`, `LIMITS_EXCEEDED`, `QUERY_UNKNOWN`, `PARAMS_INVALID`, `HEAD_MISMATCH`, `SNAPSHOT_HEAD_CHANGED`, `REF_UNRESOLVED`, per-operation `SQL_ERROR` (rolled back to its savepoint, the rest of the intent continues), `HISTORICAL_QUERY_UNSUPPORTED`, `SNAPSHOT_CLOCK_CONFLICT`. Evidence path (existing): `ArtifactLedger.putWith`/`get`/`reconcile` under content-addressed digest verification; `validatePersistedSnapshot` re-derives the snapshot digest and rejects any persisted envelope whose content, clock, or tenant disagrees with its bound intent.

Normal path (new, `space_manifest`): `buildSpaceManifest` is pure and always succeeds for well-formed input. `readSpaceManifest` inspects the catalog, executes at most one `knowledge-read-intent.v1` containing only the catalog queries that exist, and returns the manifest with the live half merged and the rest in `unavailable[]`. Failure path (new): none of its own — `readSpaceManifest` never throws for a missing catalog query (that is the documented, expected case, reported in `unavailable[]`, not an error); it would surface whatever `reads.head`/`reads.runIntent` throw (the existing `ReadExecutor` error set above) if the underlying catalog queries existed and failed.
