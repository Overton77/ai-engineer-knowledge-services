# Module review: policy

Module and reviewed revision: `@aiengineer/knowledge-policy` at `ff7fe97` plus the uncommitted 2026-09-19 addition of `packages/policy/src/selection-eligibility.ts`, its sibling test, and the one added barrel line in `packages/policy/src/index.ts`. No existing file in this package moved or changed export behaviour; this review covers the whole package, not only the new file.

Purpose, owner, callers, and supported interfaces: Knowledge Services owns policy admission decisions — authorization, capability admission, retrieval-plan authorization, promotion-decision validation, and immutable verification-policy evaluation/override — as pure functions with no I/O. Successful execution alone never authorizes publication.

Callers, measured by import (`rg "@aiengineer/knowledge-policy"`, excluding `node_modules`/`dist`):
- `apps/worker/src/verification-metric-sealer.ts`, `apps/worker/src/verification-claims-sealer.ts` (verification-policy evaluation at sealing time).
- `apps/verification-executor/src/executor.ts`, `apps/verification-executor/src/knowledge/evidence-oracle.ts`, `apps/verification-executor/src/knowledge/recovery-host-canonical.ts`, `apps/verification-executor/src/knowledge/recovery-executor-evidence.ts`.

- Four existing test files exercising the above.
- **`research_ingestion_systems_agent` imports `packages/policy/src` directly** (source, not the built package). This is the ADR 0004 violation recorded as decision **D9** (`ai-engineer-knowledge-services/docs/architecture/0004-transport-call-graph.md`: out-of-process callers must use `KnowledgeClient` HTTP, not internal algorithm packages). F9 adds one more file inside that already-violated import surface; it does not create a new violation, and it does not widen the violation's blast radius beyond "one more file the harness could theoretically reach into" — the harness does not reference `selection-eligibility.ts` today (checked: no hit in that repository for `selection-eligibility` or `evaluateSelectionEligibility`).

Affected agent skills: **none.** `promotion_selection_select` and `promotion select` stay in `skills/manifest.json`'s `absentOperations` for `knowledge-preparation-and-promotion` (decision D5, confirmed by `PHASE-2-RECOMMENDATION.md` §5.4). `node skills/check.mjs` was re-run after this change and still reports `{"skills":11,"executorOperations":42,"executorMcpTools":58,"platformCommands":78,"platformMcpTools":70}`, exit 0 — unchanged.
