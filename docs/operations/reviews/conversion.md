## Must-haves

Derived from `docs/operations/conversion-and-chunking.md` §"Must-haves (developer-facing)", conversion rows only. Assessment reflects what `packages/conversion/src/route.ts`, `conversion.test.ts`, and `examples/examples.test.ts` actually assert.

| ID | Must-have | Given / when / then | Assessment |
|---|---|---|---|
| CONV-TEXT | Plain text never calls Docling or Unstructured | Given markdown / VTT / plain text, when the router runs with Docling and Unstructured stubs that count calls, then `candidateRoute` is the text provider only and the binary count is 0 | present: `conversion.test.ts` "keeps markdown, VTT, and plain text exclusive to the text converter", "never calls Docling or Unstructured for exclusive text"; example 01 (`calls` is `[]`) |
| CONV-OOXML | Office Open XML is not treated as deterministic text | Given a `.docx`-class media type, when classified, then it is not exclusive text | present: "does not treat Office Open XML as deterministic text" |
| CONV-DOCLING | A PDF succeeds on Docling without an Unstructured key | Given a PDF with `managedProcessingAllowed: false` and no Unstructured client, when routed, then `candidateRoute` is `["docling-serve@…"]`, `fallbackUsed` is false, Unstructured is never called | present: "converts a PDF on Docling without an Unstructured key"; example 02 (no Unstructured configured; `route.ts` substitutes an absent provider) |
| CONV-GATE | Unstructured is never invoked unless managed processing is explicitly allowed | Given `managedProcessingAllowed: false`, when the router builds candidates or the provider is called directly, then Unstructured is excluded from the route (`route.ts` `structuredCandidates`) and `UnstructuredTransformProvider.convert` throws `MANAGED_PROCESSING_DENIED` without creating a job | present at both layers: "never invokes Unstructured unless managed processing is allowed" (provider), "converts a PDF on Docling without an Unstructured key" (router); example 06 (`unstructuredJobs` 0, `denied` = `MANAGED_PROCESSING_DENIED`) |
| CONV-ORDER | Router order is text → Docling → gated Unstructured, and an admitted subset cannot reorder it | Given a PDF with managed processing allowed and Docling failing, when routed, then Docling is attempted first and Unstructured second; given `admittedKeys` listed Unstructured-first, then `candidateRoute` still lists Docling first | present: "tries Docling before gated Unstructured", "respects an admitted provider subset without changing policy order"; example 04 |
| CONV-FIDELITY | Low fidelity `alternate_conversion` advances to the next admitted converter | Given Docling returns `grade: "low"` with an `alternate_conversion` finding, when routed, then attempt 0 is `failed` / `invalid_output` and Unstructured is selected | present: "tries the next admitted converter when fidelity asks for alternate_conversion"; example 03 covers the fidelity inspection itself |
| CONV-EXHAUST | No admitted converter left fails closed with typed attempts | Given only Docling admitted and failing, when routed, then `CONVERSION_EXHAUSTED:docling-serve:provider_failed` | present: "exhausts when no admitted converter remains" |
| CONV-RECEIPT | Routing receipt records candidate route, typed attempts, selected provider, and `fallbackUsed`; it is deterministic for the same request | Given two identical conversions, when compared, then receipts are equal and attempt 0 carries `providerKey`, `outcome`, `failureClass` | present: "tries Docling before gated Unstructured" (`first.receipt` equals `second.receipt`, `attempts[0]` shape, `fallbackUsed`); `candidateRoute` / `selectedProviderKey` asserted across the router tests and the examples test |
| CONV-SECRETS | Credentials never appear in URLs, errors, or the routing receipt | Given a provider error carrying a secret-like token, when the receipt is sealed, then the serialized receipt does not contain it; given HTTP clients with an API key, when a request is made, then the key is in a header and not the URL | partial: receipt absence asserted ("tries Docling before gated Unstructured", example 04); URL absence asserted for Unstructured ("configures Unstructured on-demand auth without placing keys in URLs or errors") and Docling ("calls the bounded Docling Serve v1 multipart API…"). No test asserts that a thrown client error message omits the key; `route.ts` keeps only `failureClass` in attempts, so the receipt path is covered by construction, but error text from the clients is not asserted |
| CONV-IMPORT | Vendor MCP is not a dependency of our process; import is receipts | Given stored vendor markdown, when converted, then nodes come from our deterministic provider; given `package.json`, then only `@aiengineer/knowledge-domain` and `@aiengineer/knowledge-runtime` are dependencies | present for this package: example 05 ("stored vendor markdown → our nodes", `nodes.length > 1`); dependency graph has no vendor client. The receipt handshake itself (`source_import`) lives in the executor and is not exercised here |
| CONV-WORKER | Worker intersects the caller `providerRoute` with policy order; Unstructured cannot jump the queue | Given a `providerRoute`, when the durable convert step runs, then it passes `admittedKeys` to `convertWithReceipt` | partial: `activity-registry.ts:650–660` passes `admittedKeys: input.providerRoute`; `activity-registry.test.ts` runs with `providerRoute: ["deterministic-structural-text"]` only, so the reorder case is covered by the package test (CONV-ORDER), not by a worker test |
| CONV-PARSER | The isolated verification parser is not a general converter | Given the sandboxed parser, when admission runs, then mutable image names, mismatched identity, and oversized inputs are rejected before any process starts | present as a boundary: `verification-parser.test.ts` (4 cases); locator/quote geometry behavior is owned by `docs/operations/reviews/verification.md`, not re-reviewed here |

Normal path: sealed artifact → media-type classification → text provider, or Docling for PDF / Office / hard HTML, or Unstructured when `managedProcessingAllowed` → nodes + fidelity + routing receipt. Failure path: `CONVERSION_EXHAUSTED:<provider>:<failureClass>` with typed attempts (`policy_denied`, `timeout`, `provider_unavailable`, `invalid_output`, `provider_failed`), `MANAGED_PROCESSING_DENIED`, `DOCLING_URL_DENIED`, `DOCLING_RESULT_SIZE_LIMIT`, `CONVERSION_PROVIDER_ABSENT`. Recovery: `alternate_conversion` means the next admitted converter; a `CONVERSION_EXHAUSTED` result is repaired by admitting another converter or quarantining, never by a session-local parser.

Provider restrictions: do not move Docling or Unstructured into acquisition; do not re-host Unstructured Transform or grow a product wrapper; Unstructured stays the gated, paid safety net; credentials stay in headers and out of receipts.

Evidence: `packages/conversion/src/conversion.test.ts` (16 cases), `packages/conversion/src/verification-parser.test.ts` (4 cases), `packages/conversion/examples/examples.test.ts` (6 examples), `packages/conversion/src/route.ts`, `docs/operations/conversion-and-chunking.md` §"Observed after the conversion cleanup". Checks run 2026-09-19: `corepack pnpm --filter @aiengineer/knowledge-conversion typecheck`, `test` (3 files, 20 tests), `examples`.

Explicitly skipped checks: live Docling Serve (`scripts/live-docling-conversion.ts`), live Unstructured Transform, Docker-backed verification parser execution, worker durable convert against a database.
