# Final acceptance and requirement traceability

Date: 2026-09-03; refreshed 2026-09-04 UTC

## Acceptance verdict

The implementation has local, inspectable evidence for the 13 bounded standalone-prototype Definition of Done items. Gates 0–4 are proved. Gate 5 remains **partial against its literal wording** because deterministic grading, a live model judge, and independent agent review ran, but no sampled-human grading receipt exists. Gate 6 is proved for its bounded component and durability harnesses but remains **partial for a general multi-process production topology**: PostgreSQL-configured API and MCP admission are visible to the canonical worker, while the worker bootstrap still needs real operation-kind handlers. The repository calls the human-review limitation out in `catalog/broad-corpus-review-history.json`, and the runtime boundary is documented in `docs/OPERATOR_RUNBOOK.md`.

No remote deployment, official-canonical publication, or shared remote-data mutation was performed. Live provider, Gateway, Eve, and app receipts are bounded and explicitly noncanonical. Local database/Storage proofs use the dedicated `internal_exploratory` tenant only.

Status meanings:

- **Proved**: exercised by current tests and/or a digest-verifiable receipt.
- **Partial**: most behavior is proved, but an explicit requirement remains unproved.

## Final hardening findings fixed

1. API routes now fail closed on missing/mismatched tenant, actor, action, and correlation context.
2. Callback IDs are single-use and timestamp-bounded.
3. Artifact reads/replays verify bytes against their digest and detect tampering.
4. Operation IDs cannot be reused under a different idempotency key.
5. Embedding text digests, projection uniqueness, output order, finiteness, model, and dimensions are validated.
6. Retrieval candidate/final limits, RRF, coverage, filters, and publication-bound identities fail closed.
7. HTTP/Firecrawl paths bound bytes, redirects, decompression, credentials, IPv4/IPv6 special ranges, and response redaction.
8. Store-space authority must match its parent store; outbox event references are tenant-composite.
9. Canonical persistence materializes and verifies evidence packet/member rows, source-native identities, private object references, and fenced outbox operations.
10. The v7 durability proof initially failed on a second execution because fixed IDs encountered the prior immutable v1 packet after the proof had left v3 active. The runner now records a unique execution namespace, preserves all prior immutable rows, and passed twice consecutively.
11. Evidence-packet claim and knowledge-subject references are now tenant-composite, and evidence-gate lookups explicitly constrain the packet tenant; pgTAP verifies all ten tenant FKs.
12. Evidence-packet replay now validates the retrieval run-to-plan binding and normalized plan content, rejecting conflicting immutable reuse.
13. Lease capability tokens are no longer serialized into operation events or outbox payloads; a local persistence regression test inspects both durable rows.
14. The direct HTTP production transport now connects to the validated address without a second DNS lookup, preserves the original Host header, enables HTTPS certificate verification against the original DNS name through SNI, rejects forbidden addresses again at the transport boundary, and retains redirect-by-redirect policy validation. Rebinding and IPv4/IPv6 regression cases pass.
15. Canonical fixture reviewers are honestly identified as `local-review-fixture`; neither the current receipt nor documentation represents the automated fixture as human review.
16. The pending Gate 5 human packet now uses opaque sample-local case/result/graph identities and withholds original case digests, query-class, partition, fixture, decoy, and system citation-verdict hints. Validation locks the canonical 24-case specification, binds the public execution-input manifest, rebuilds actual hybrid-control outputs and hidden references, and digest-compares the complete packet. Retrieval relevance penalizes irrelevant additions as required by the human rubric. No human grades or receipt were fabricated during this hardening pass.
17. The broad evaluation runner no longer plans with domain/query-class labels, expected filters, or positive qrels. A deterministic planner accepts only the explicit public query/requested-spaces request and the tenant/language/visibility/active-version runtime contract; labels and expectations are evaluation-only. A poisoning regression changes domain, query class, qrels, filters, and required result types, reruns the actual packets, and proves identical packet digests/results. The regenerated 96-case evaluation passes every gate with zero false acceptances.

## Residual limitations

- A sampled-human grader has not run, so literal Gate 5 is not complete even though DoD 6 passes.
- With `POSTGRES_URL`, API and MCP operations are durably admitted and consumed by the separately started PostgreSQL worker; MCP verifies the same bearer-bound actor/tenant authorization and returns API-rooted status links.
- The canonical worker rejects unregistered activities rather than recording a generic success. Concrete capture, conversion, chunking, reviewer-decision, projection, embedding, guarded publication/rollback, and retrieval-packet activities are registered with complete durable inputs; API-owned canonical retrieval is intentionally excluded from generic worker leases.
- Gate 1 recorded Unstructured as unconfigured; real direct HTTP and Firecrawl ran, and the denied-managed-to-local fallback is deterministic.
- The held-out suite is structurally comprehensive but partly synthetic and grounded in only three real source families.
- Local HNSW planning/recall does not predict each deployed database planner.
- Remote identity, queue, network-policy, secret rotation, and deployment topology still require environment acceptance. These are deployment-only and do not invalidate the standalone DoD proof.

## Final decision

The bounded standalone prototype demonstrates Definition of Done items 1–13 and is suitable for further supervised exploratory use. It should **not** be described as a complete production multi-process service or as satisfying every literal specification gate. Literal Gate 5 requires a sampled-human grading receipt. General Gate 6 additionally requires the remaining operation-specific worker activities and deployment-specific identity, queue, network, and infrastructure acceptance. Official-canonical publication remains a separate supervised/deployment decision and was not authorized by this acceptance pass.
