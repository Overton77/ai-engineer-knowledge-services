The earlier gap statement about `CAPTURE_READ_RECEIPT_HYDRATION_GAP` is superseded. Current `PostgresCaptureReadRepository` hydrates and verifies the exact acquisition-receipt handle, canonical receipt bytes, tenant/operation/source/content binding, response metadata, receipt transformation signature, and capture transformation signature before projection readmission (`packages/persistence/src/verification-capture-reads.ts:79-107`). The prior retained audit remains historical evidence of the defect, not a current open finding.

The earlier “single native proof joining everything” wording is also withdrawn. VR028 can compose independent authoritative proofs when each proof is source-bound and current. Current retained evidence includes native source acquisition/read closure (the b7f8… receipt above), native capture/parse terminal parity with an actual sandboxed parser worker (`internal/verification-capture-terminal-parity-e294513b-bb26-4bfd-8f94-85d58de9ce2a.json`, `internal/verification-parse-terminal-parity-be326c7d-a756-4446-90c6-7c38d4032d1e.json`), and native gateway claims/report custody/accounting controls (`internal/verification-semantic-native-gateway-35b43d5a-75a9-44e7-a130-98617401a759.json`). These materially reduce the remaining scope; no reimplementation of fixed receipt or parser controls is recommended.

The remaining provider limitation is narrower: the retained native gateway proof demonstrates one configured native gateway composition, strict custody, request/observation binding, replay/drift rejection, and accounting controls, but its own scope calls the audit/mechanical input fixture synthetic. It does not establish every deployed provider account’s privacy terms or a claims/report v2 semantic-quality campaign. The pending Terra work is parser-only and should be counted only for parser evidence, not as provider v2 proof.

Revised smallest remaining work is therefore: (a) retain the corrected source-read/native parser receipts as current VR028 evidence; (b) independently inspect the Terra parser receipt when supplied for exact immutable-image and hostile-file assertions; (c) inspect the current provider-policy/native gateway receipts against the configured deployment policy and retain a narrowly scoped safe provider fixture if needed; and (d) close only any specific public-route redaction or deployment-control assertion still absent from the route inventory.
