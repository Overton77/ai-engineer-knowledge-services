# Durable benchmark comparison handoff

Coordinator review, 2026-09-06 UTC. Accepted bounded evidence: EV-072 and EV-073. Public comparison worker, HTTP/client/CLI/MCP and process-kill recovery remain the next implementation slice. The full module goal remains active.

The registered-profile application resolves exact tenant-granted profile bytes and two signed succeeded benchmark publications, then hydrates their exact dataset/runner bytes. It validates publication/run/plan/arm-summary bindings, bounds total bytes and statistical work, and computes a global Holm family across registered arm pairs. Same-process preparation authority is bound to the tenant and parsed request with a private WeakMap. Current scope is single-repetition, recorded offline engineering observations; no human-gold, independence, population, authority, calibration or promotion claim.

The durable store binds comparison/operation IDs, both original run and publication IDs/digests, profile, runtime and attempt. DB clock timestamps survive retries. Only running → completed → sealed transitions are permitted. The store locks the canonical operation and validates the live step/lease; the SQL trigger independently requires its transaction-local token/fence/holder/step claim. Immutable metadata must contain exact result/publication parents and a v2 transformation signature binding byte digest, semantic digest and publication identity/runtime/timing. The signature encoding is UTF-8, pipe-delimited fixed-type fields; ordered parents contain UUIDs only. Registered result content remains validated by trusted application preparation; SQL does not independently parse Storage content or verify Ed25519.

The publication builder requires branded preparation, exact retained result registration and a signer. It emits `verification_benchmark_comparison_publication`, separately from ordinary benchmark manifests. Completion guards require a sealed comparison before step success, exact event/receipt/output binding, and one successful receipt before operation success. Prototype internal publications retain their original rows but cannot newly succeed using the earlier generic artifact type.

### Worker activity slice

The bounded EV-073 continuation adds `verificationBenchmarkComparisonActivityHandler` and seven focused unit tests. The activity re-prepares trusted inputs on every attempt, derives the comparison ID from tenant and operation, uses durable database timestamps, re-registers the exact content-addressed result/publication, and relies on the fenced comparison store for retry drift detection. Fresh operation reads are serialized so cancellation polls cannot overlap. The activity checks canonical tenant/operation identity, runtime attempt, prepared request identity, completed result custody, sealed publication custody and the engineering-only quality claims before returning the canonical `verification-operation-result.v1` body. It does not complete the canonical step; the worker executor retains that boundary.

Focused validation passes: seven activity tests and strict worker TypeScript compilation. These cover first execution, sealed retry timing/custody reuse, exact durable result drift, tenant and attempt mismatch, non-overlapping cancellation polling, retryable infrastructure error preservation and malformed request rejection.
