# Optional semantic worker runtime

The claims/report worker can grade mechanically admitted evidence and retain the assessment and provider custody in its sealed audit. This path is opt-in. The default remains deterministic-only. Semantic support alone does not establish independent source authority; the sealer still forbids admission outcomes until the remaining requirements are implemented.

The tested R17 SQL was promoted to canonical migration `20260907013000_verification_semantic_provider_observation.sql` and applied to the local database on 2026-09-07. Database contract 0.2.34 includes the generated types. Isolated native receipts cover the worker stage, sealed audit and accounting reconciliation; EV-120 additionally proves the local Temporal/public semantic lifecycle with configured worker, real Luna, signed sealing and typed terminal reads. Cross-family calibration and production deployment remain unproved. No runtime grants were enabled by migration promotion.

Configuration is owned by the server:

- `VERIFICATION_AUDIT_SIGNING_KEY_ID` and `VERIFICATION_AUDIT_SIGNING_PRIVATE_KEY_PEM`: optional paired Ed25519 settings for the configured metric and claims/report sealers. Startup rejects partial, oversized, malformed, or non-Ed25519 settings before opening persistence. Deployments without either setting retain unsigned sealing. Configure the corresponding public key separately for terminal readers; never retain the private key in receipts, logs, or Temporal history.
- `VERIFICATION_SEMANTIC_RUNTIME_JSON`: a strict JSON object with `classification` (`synthetic` or `public`), integer `ceilingCostMicros`, integer `reservationCostMicros`, and integer `deadlineMs`. Both costs must be positive and at most 20,000,000 micros; reservation cannot exceed ceiling. Deadline is 1,000–300,000 ms. The classification must describe the authorized evidence for the granted operations.
- `VERIFICATION_SEMANTIC_PROFILE_GRANTS_JSON`: exact tenant/operation/host grants with primary and optional cross-family judge roles. The catalog authorizes and hydrates the full registered profile artifact before invoking its judge. It validates canonical bytes and identity. The same grants support retained audit replay.
- `AI_GATEWAY_API_KEY`: Gateway credential. Never retain its value in an audit or progress ledger.

There are no implicit model grants. Supported Gateway adapters currently accept Luna, Terra, and Haiku model identifiers defined in the provider adapter. Profile identities must match its model family, prompt, configuration and output-schema digests. The application checks producer/verifier separation before invoking a judge. The second judge remains lazy and is invoked only when the core semantic policy requires it.

The activity passes its actual full lease alongside the sealer claim. The stage rejects mismatched tenant, operation, host, step, token, fence or holder before grading. Every judge shares one durable operation budget, with a deterministic logical provider attempt bound to the profile and blinded input. Recovery uses the factory's original captured attempt without redispatch. After grading, the stage reads the matching native observation and transport roots, authorizes and checks retained bytes, and the sealer includes their ancestor closure. The service validates its privately issued assessment batch before sealing.
