# Verification native parser boundary

This is a separate, bounded parsing route for native PDF text/word geometry and UTF-8 HTML DOM. It does not replace Docling or perform OCR. The TypeScript entry point is `SandboxedVerificationParser` in `packages/conversion`; pure verification selectors never start processes.

Build with `docker build -t aiengineer-verification-parser:v1 services/verification-parser`, then obtain its immutable local image ID with `docker image inspect --format '{{.Id}}' aiengineer-verification-parser:v1`. Configure the adapter with that ID, not the mutable tag. Deployment configuration is trusted; requests cannot choose an executable, image, URL, path, mount, environment variable, or command. The base image digest and Python dependency versions are pinned. The final image ID is included in each transformation signature; rebuilding requires admission of the resulting image.

Every job uses network `none`, a read-only root, an unprivileged user, dropped capabilities, no new privileges, 32 PIDs, one CPU, 512 MiB memory with no extra swap, and a 64 MiB noexec temporary filesystem. The parser additionally limits CPU to 15 seconds (hard kill at 16), address space to 512 MiB, individual file size to 8 MiB, and open files to 64. The adapter gives creation, execution, and inspection one shared 45-second deadline, limits input to 8 MB and stdout to 4 MB, and refuses to start a later phase after that deadline. Container removal then has a separate 10-second cleanup bound, so a cleanup failure is explicit even after timeout or cancellation. No host directory or Docker socket is mounted into the container.

PDF admission limits pages to 40 and each page to 100,000 characters and 10,000 words. Page numbering is physical and one-based. Native text does not establish values present only in figures or image layers: all pages retain visual residuals. Invalid word boxes are omitted with an explicit residual. HTML preserves mixed text/element order, extracts ID into `node.id`, and excludes declared hidden/inert content from canonical visible text. Computed CSS, external styles, JavaScript and browser layout are not executed; a residual requires another admitted route or abstention for claims dependent on those features.

The adapter returns bounded native bytes and untrusted projection objects. Application composition must canonicalize and validate each projection with `parseCanonicalProjection`, register the raw and derived artifact handles, bind capture and transformation lineage, and authorize hydration before verification. Successful process execution alone is not projection admission or evidence acceptance.

Coordinator proof uses the real restricted 24-page sample PDF and captured TruDiagnostic HTML, plus synthetic hostile/boundary inputs. Outputs remain outside distributable source in the restricted capture workspace. CPU, memory, disk, network, root-write, page-limit, cancellation and cleanup probes are recorded in `docs/workspaces/verification-module/HANDOFF-WS-04-PARSER.md`. This implementation still requires independent review and registered-lineage integration before WS-04 completion.
