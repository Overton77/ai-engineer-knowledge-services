# Local Git-driven maintenance pilot

Run with Node 24 from the repository root:

```sh
node tools/maintenance/cli.mjs doctor
node tools/maintenance/cli.mjs reconcile
node tools/maintenance/cli.mjs run --dry-run
node tools/maintenance/cli.mjs status
node --test tools/maintenance/*.test.mjs
```

`policy.json` enables isolated proposals through Cursor only, pinned to `grok-4.7-high` (Grok 4.7, high reasoning, non-fast). A different provider or model is rejected. Set `observe` to `true` for observation-only operation. The wrapper requires `CURSOR_API_KEY` from the original repository's `.env` or environment; it selectively extracts that key and never loads other `.env` values. Credentials are not copied to proposal worktrees. Cursor's native Windows installation is resolved from `%LOCALAPPDATA%/cursor-agent/versions`; otherwise `agent` must be on PATH. `doctor` checks installed model availability without making a generation request. Maintenance agents use an empty per-attempt home and Cursor configuration/data directories so personal MCP servers and unrelated global settings are not inherited. Your normal Cursor configuration is unchanged. Cursor can still initialize account-managed plugins independently; an empty file-based MCP inventory does not prove those are disabled. The prompt forbids MCP use, production access, delegation and model changes. This is not an OS sandbox.

Actual Git hooks enqueue committed work; the independent OS supervisor runs `watch --once` every minute to reconcile missed events and process the same queue. It is not a permanently resident process. Cursor hooks add immediate handling of uncommitted task edits. `pause` stops new claims and `resume` restores them; neither interrupts an already running provider. Failures before a valid review have bounded retries with separate evidence for each attempt. Once a valid review exists, failed validation does not trigger another paid review of the same input.

Project hooks in `.cursor/hooks.json` use `beforeSubmitPrompt` for a Git baseline, `afterFileEdit` and `afterShellExecution` for cheap markers, and completed `stop` for deterministic gating. No new eligible bytes, read-only work against a preexisting dirty tree, duplicate snapshots, excluded-only edits, aborted/error stops, maintenance children and maintenance branches skip the model. An eligible dirty snapshot uses a temporary index and immutable Git objects without touching the developer branch or staging. Git text normalization preserves Windows CRLF checkouts while storing canonical blobs; custom clean filters are rejected before snapshot inspection. One bounded follow-up runs `node tools/maintenance/cli.mjs run --provider cursor --job <id>`; the wrapper, not the active task's selected model, launches Grok. The scheduled worker is a fallback. Without a baseline, shell-only events skip; an eligible file-edit event can still trigger a review.

`install-hooks` installs managed dispatchers in the Git common directory and sets a repository-local absolute `core.hooksPath`. Existing custom hooks or another hooks path (including inherited configuration) are refused and preserved; manually chain the CLI commands if you already have hooks. `uninstall-hooks` only removes this engine's managed hooks. Nothing installs automatically. Post-commit, post-merge, post-checkout and post-rewrite enqueue quickly; pre-commit checks staged whitespace, agent-docs JSON syntax and source formatting through Biome stdin without changing staging. Dependencies must be installed before staged formatting works. Generated documentation semantic freshness is checked in the proposal checkout and CI, not against unstaged working files in pre-commit. Pre-push reads Git's exact outgoing SHA rows. Push receipt enforcement is optional and disabled by default. Only an unchanged checkout validated at that exact SHA counts as a receipt; a changed proposal does not certify the original commit. Remote CI remains authoritative.

The queue is SQLite at `<git-common-dir>/maintenance/state.sqlite`, shared across worktrees. Jobs are keyed by commit/input and policy fingerprints, fenced with lease tokens, and processed by one writer. Working-tree fingerprints include content and staged identity, so equal Git status text does not conceal changed contents. The watcher observes working changes; Cursor hooks can enqueue an immutable snapshot of eligible dirty files. Paid work starts from a commit or snapshot revision. Eligible content is sent to Cursor for review only after deterministic gating. Maintenance branches cannot enqueue themselves. Jobs whose source HEAD or captured dirty fingerprint no longer matches the initiating checkout are superseded.

Agent work runs in a separate `maintenance/<job>-<attempt>` branch and worktree under the Git maintenance directory. It must review code quality, semantic documentation and meaningful test gaps together, obey repository instructions, preserve sealed evidence, and avoid production services. Validation runs in that checkout. Output includes the prompt, provider response, check logs, a binary patch, patch digest and receipt, even after failure. No changes are applied to the developer checkout, staged there, committed, pushed or merged. Worktrees remain for inspection and recovery; use `git worktree` to inspect them and remove only after preserving wanted changes.

The default full validation explicitly installs dependencies with `pnpm install --frozen-lockfile --ignore-scripts`, checks generated documentation and runs `pnpm verify`. Docs-only changes use the generated-doc check when every committed/proposed path matches the explicit documentation/metadata allowlist; executable updater files and tests always use full validation. Known baseline failures remain failed receipts. Provider processes receive a small environment allowlist, including only the selected Cursor API key and a recursion guard, with no database configuration. Known provider credentials are redacted from logs. This is operational containment, not an OS security sandbox: authenticated agent CLIs retain their own permission/configuration behavior, and Git worktrees share repository metadata. Run only on trusted local repositories.

The agent must write a validated `review-evidence.v1` report with a summary, findings, test reasoning, documentation dispositions and evidence, changes and limitations. Empty test/documentation assessments are rejected; unchanged documentation needs a reason. Protected path edits, missing reports, changed Git history, stale initiating HEAD and failed checks cannot become accepted proposals. Each attempt is retained separately. Snapshot and patch byte budgets are 2 MiB per file and 20 MiB total. Snapshot candidates are limited to changed explicit source/documentation paths and exclude artifact/output/fixture trees before Git enumeration. These limits intentionally surface a failure for oversized changes instead of silently reviewing truncated content.

Before each paid call, `context.mjs` writes a bounded context packet beside the attempt receipt: changed paths, Git diff/whitespace status, relevant knowledge routes and matching open-PR metadata if GitHub CLI is available. Each subprocess has a five-second timeout; unavailable services remain explicit. The model prompt requires justified changes only: leave correct code, accurate documentation and adequate tests unchanged. No checklist-filling refactors or repetitive tests.

Cloud Cursor task environments need Node 24, Git, Cursor CLI and their own `CURSOR_API_KEY` secret. Repository command hooks operate in writable cloud environments; local secrets and the Windows supervisor do not travel with Git. GitHub API maintenance dispatch is separately pinned to Grok 4.7 and suppresses nested maintenance.

Pilot limits: no automatic application to your checkout, merge or deployment proof. Dirty snapshots are bounded to 80 eligible files. Tests use disposable Git repositories and fake providers; live smoke evidence is separate. Full application validation still reports the known missing sealed replay checkpoint. See `docs/operations/agent-maintenance.md` for operation and remote setup.
