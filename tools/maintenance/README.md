# Local Git-driven maintenance pilot

Run with Node 24 from the repository root:

```sh
node tools/maintenance/cli.mjs doctor
node tools/maintenance/cli.mjs reconcile
node tools/maintenance/cli.mjs run --dry-run
node tools/maintenance/cli.mjs status
node --test tools/maintenance/maintenance.test.mjs
```

`policy.json` enables isolated proposals for this pilot after a real-provider smoke test. Set `observe` to `true` for observation-only operation. Choose `provider` (`codex`, `claude`, `cursor`), total job timeout, retry bound, polling interval and validation commands. Commands are executable/argument arrays, never shell strings. Provider CLIs must already be installed and authenticated. The engine never reads `.env`; credentials must be supplied explicitly by the launching environment. Do not commit credentials. Windows Codex, Claude and Corepack npm installations are resolved to their Node entrypoints without a shell. Cursor's native Windows installation is resolved from its versioned `%LOCALAPPDATA%/cursor-agent/versions` directory; otherwise an executable `agent` must be on PATH.

Run `watch` from an independent OS supervisor to reconcile Git state and process queued commits automatically. `watch --once` performs one iteration. Editor/session hooks are not used. `pause` stops new claims and `resume` restores them; these commands do not interrupt an already running provider. OS process termination stops the worker; expired jobs are reclaimable after their bounded lease. Failed jobs retry up to `maxAttempts`, with each attempt retaining its own checkout and evidence.

`install-hooks` installs managed dispatchers in the Git common directory and sets a repository-local absolute `core.hooksPath`. Existing custom hooks or another hooks path (including inherited configuration) are refused and preserved; manually chain the CLI commands if you already have hooks. `uninstall-hooks` only removes this engine's managed hooks. Nothing installs automatically. Post-commit, post-merge, post-checkout and post-rewrite enqueue quickly; pre-commit checks staged whitespace, agent-docs JSON syntax and source formatting through Biome stdin without changing staging. Dependencies must be installed before staged formatting works. Generated documentation semantic freshness is checked in the proposal checkout and CI, not against unstaged working files in pre-commit. Pre-push reads Git's exact outgoing SHA rows. Push receipt enforcement is optional and disabled by default. Only an unchanged checkout validated at that exact SHA counts as a receipt; a changed proposal does not certify the original commit. Remote CI remains authoritative.

The queue is SQLite at `<git-common-dir>/maintenance/state.sqlite`, shared across worktrees. Jobs are keyed by commit/input and policy fingerprints, fenced with lease tokens, and processed by one writer. Working-tree fingerprints include content and staged identity, so equal Git status text does not conceal changed contents. Working changes are observations only: they do not trigger edits or get uploaded. Paid work starts from committed revisions. Maintenance branches cannot enqueue themselves. Jobs whose head differs from the initiating checkout's current head are superseded.

Agent work runs in a separate `maintenance/<job>-<attempt>` branch and worktree under the Git maintenance directory. It must review code quality, semantic documentation and meaningful test gaps together, obey repository instructions, preserve sealed evidence, and avoid production services. Validation runs in that checkout. Output includes the prompt, provider response, check logs, a binary patch, patch digest and receipt, even after failure. No changes are applied to the developer checkout, staged there, committed, pushed or merged. Worktrees remain for inspection and recovery; use `git worktree` to inspect them and remove only after preserving wanted changes.

The default full validation explicitly installs dependencies with `pnpm install --frozen-lockfile --ignore-scripts`, checks generated documentation and runs `pnpm verify`. Docs-only changes use the generated-doc check when every committed/proposed path matches the explicit documentation/metadata allowlist; executable updater files and tests always use full validation. Known baseline failures remain failed receipts. Provider processes receive a small environment allowlist, including provider API keys but no database configuration. Known provider credentials are redacted from logs. This is operational containment, not an OS security sandbox: authenticated agent CLIs retain their own permission/configuration behavior, and Git worktrees share repository metadata. Run only on trusted local repositories.

The agent must write a validated `review-evidence.v1` report with a summary, findings, test reasoning, documentation dispositions and evidence, changes and limitations. Empty test/documentation assessments are rejected; unchanged documentation needs a reason. Protected path edits, missing reports, changed Git history, stale initiating HEAD and failed checks cannot become accepted proposals. Each attempt is retained separately. Snapshot and patch byte budgets are 2 MiB per file and 20 MiB total. Snapshot candidates are limited to changed explicit source/documentation paths and exclude artifact/output/fixture trees before Git enumeration. These limits intentionally surface a failure for oversized changes instead of silently reviewing truncated content.

Pilot limits: this engine records working-tree changes but does not snapshot dirty content into agent jobs; semantic work starts at commits. It does not auto-merge, install an OS service, manage remote GitHub reviews, or prove deployment. Tests use disposable Git repositories and fake providers. Real provider smoke tests and a supervised initial run are required before unattended use.
